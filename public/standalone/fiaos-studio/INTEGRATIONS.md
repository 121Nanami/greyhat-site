# fiaOS integrations
Run `npm start` (Node 18+, no dependencies) → http://localhost:8080. Optional: set `XAI_API_KEY` in the environment before `npm start` so the Grok key stays on the server, not in the browser. This demo ships no key.
Verified live from the build box on 22 Oct 2026 (UTC).

| Integration | Status | Provides | How it connects in fiaOS |
|---|---|---|---|
| Open-Meteo weather + geocoding | **Live** (verified) | Current temp/feels-like/UV, hourly rain %, 3-day forecast; location search | Direct browser fetch (CORS OK, works even from file://). Rain ≥60% / wet code → indoor workout; feels-like ≥32°C → shorter/early session |
| Open Food Facts | **Live** (verified) | Name search and barcode lookup, kcal + macros per serving (or per 100 g) | Barcode: direct (CORS OK). Name search: via `/api/off` proxy (legacy search blocks CORS and was returning 503 during testing; the proxy falls back to search-a-licious + product lookups) |
| ICS / Google Calendar / uni timetable | **Live** via proxy (verified with Google's public AU holidays feed) | Events into the Setlist; keywords (exam/final/midsem/quiz/test → exam; assignment/due/essay/report/submission… → assignment) auto-create exams (→ study blocks, lighter workouts) and assignments | Settings → ICS URL. Google: Settings › your calendar › "Secret address in iCal format". Fetched through `/api/ics` (Google sends no CORS headers, so direct browser fetch fails, with an in-app note) |
| Google Calendar (per profile) | **Built, needs one-time owner setup** (Google Cloud *Desktop* OAuth client). Tested with mocks only | All calendars (60 days) merged into the Setlist; exam/assignment keywords auto-create Study items; optional write-back of study blocks (`calendar.events`, off by default) | OAuth 2.0 loopback + PKCE done on the Surface itself (`http://127.0.0.1:8080/oauth/google/callback`). Google's TV/limited-input *device* flow does **not** allow Calendar or Gmail scopes (verified against Google's allowed-scopes list), so it can't be used. Refresh token stored server-side in `/var/lib/fiaos/accounts.json` (0600). ICS link stays as the zero-setup fallback |
| Gmail (per profile) | **Built, needs owner setup** (same Google client, `gmail.readonly` = restricted scope) — or **Gmail IMAP + app password** (no Cloud setup) | Inbox card: unread count + latest subjects; bills/receipts → Money suggestions, due dates/exams → Study suggestions (tap Add/Ignore) | Gmail API with the same loopback login. Unverified personal app: Google shows a "hasn't verified this app" warning; keep the app *In production* (Testing mode expires refresh tokens after 7 days). IMAP alternative: `imap.gmail.com:993`, needs 2-Step Verification + an app password |
| Outlook.com / Hotmail / uni Microsoft 365 (per profile) | **Built, needs owner setup** (free Entra app registration, public client). Tested with mocks; live endpoint answered correctly to a fake client ID | Mail (unread + latest) **and** Outlook calendar into Setlist; same detection | Microsoft identity **device code flow** (code + QR on screen, approve on phone) + Graph `Mail.Read Calendars.Read User.Read offline_access`. Basic-auth/app-password IMAP no longer works for Outlook.com or Exchange Online, so IMAP is refused for those hosts. **Uni tenants may block user consent** (AADSTS65001/90094 → fiaOS shows "ask IT to approve"); fallback: uni calendar ICS link |
| Other email (generic IMAP, per profile) | **Live code**, tested against a local fake IMAP server (login, STATUS, header fetch, MIME-word decoding, bad-password error) | Same inbox card + detection | Read-only `EXAMINE` over TLS 993 with an app password; password stored server-side only |
| NotebookLM — official Enterprise API | **Built, optional, paid**: needs a Google Cloud project with NotebookLM Enterprise licences; API is Preview (`v1alpha`) | Create a notebook per subject from fiaOS with a generated study pack as a source; list recent notebooks | `discoveryengine.googleapis.com/v1alpha/.../notebooks` + `sources:batchCreate`, using the Google login with `cloud-platform` scope. Works only for Enterprise (Workspace/Cloud identity) notebooks, **not** personal notebooklm.google.com |
| NotebookLM — your own (consumer) account | **Built, opt-in, UNOFFICIAL** via community `notebooklm-py` (MIT; undocumented Google APIs, may break anytime) | Same: create notebook + add study pack source, list notebooks — on Bea's normal NotebookLM | Install with `FIAOS_NOTEBOOKLM=1`; log in on the Mac (`notebooklm -p bea login`), import cookies with `sudo fiaos-notebooklm-import bea storage_state.json`. Cookies = full Google session; that's why it's opt-in. There is **no official consumer NotebookLM API** |
| NotebookLM — no-setup | **Live** | Study tab: per-subject notebook links, Markdown study pack download (upload as a source), QR to open on phone | Pure client side |
| Woolworths product search | **Live** via proxy (verified: 17/17 shopping-list items priced) | Real current shelf price, pack size, product link | `/api/woolies` calls the unofficial `apis/ui/Search/products` endpoint used by woolworths.com.au, after a homepage visit for cookies. Unofficial and may change or be bot-blocked (a cookie-less call got HTTP 403). If it fails: falls back to search links |
| Woolworths cart / ordering | **Needs Bea's account** (+ browser automation) | Add-to-cart, checkout, delivery slots | No public API or add-to-cart deep link. fiaOS gives per-item links plus "Open cart". Auto-ordering would need Playwright on Bea's logged-in session, with Bea confirming checkout |
| xAI Grok API | **Needs a key** | Negi-chan assistant with JSON actions | Browser key (Settings) or server env `XAI_API_KEY` via `/api/grok` (server mode verified; a real completion was not tested, no key) |
| Bank feeds (Basiq CDR, Up API) | Needs Bea's account | Real transactions → expenses | Basiq consent flow or Up personal token + webhooks |
| Apple Health / Google Health Connect / Strava / Garmin / Fitbit | Needs Bea's account | Steps, workouts, sleep, HR | Companion app/Shortcuts export or OAuth APIs |
| Uni LMS (Canvas/Moodle/Blackboard) | Needs Bea's account (or ICS — Live) | Assignments, grades | Most LMSs export an ICS feed, which works now; the full API needs a token |
| Splitwise / utility providers | Needs account | Housemate settle-up, bill amounts | Splitwise OAuth; email parsing |
| Spotify / YouTube playback | Links only (Live) | Song of the day | YouTube search links; playback control would need Spotify OAuth |
| Woolworths official partner API | **Not possible** | — | No public developer API exists |
